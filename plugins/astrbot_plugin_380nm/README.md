# 380nm · AstrBot 精简插件

使用 `/bd <X链接> [标题] [时间]`，复用 380nm 的「链接抓取」功能，将**原图、作者原文、作者姓名、@handle 和来源链接**一起保存到普通草稿。标题和时间可分别省略，成功后返回该草稿的直接编辑地址。即使设置了时间，也只保存草稿，需在网页入队后才会发布。

v1.1.0 将入口统一为 `/bd`：裸链接不再自动抓取，原 `/380队列`、`/队列状态`、`/380帮助` 入口已移除。

## 已实现的范围

| 功能 | 行为 |
| --- | --- |
| X 链接抓取 | 授权用户使用 `/bd <X链接>`，支持 `x.com`、`twitter.com`，包括 `www`、`mobile`、`m` 子域、`/i/web/status/…` 和图片后缀链接。 |
| 抓取后存草稿 | 使用 380nm 原有抓取接口及服务器上的 X 凭据、代理设置；同一条推文的原图合并到一条草稿。 |
| 保留作者说明 | 保存推文原文、作者姓名、`@handle` 和来源 URL。“作者说明”指这条推文的原文，不是作者个人简介。 |
| 专用草稿模板 | 自动查找或创建名为 `AstrBot X 草稿` 的普通动态模板，内容为 `{{content}}`。可在网页草稿页继续修改。 |
| 重复草稿检查 | 相同推文不重复抓取；再次指定标题或时间时更新已有草稿的相应字段，省略字段保留原值。仅检查当前账户现有草稿。 |
| 自定义标题与中文时间 | 每次一个作品，标题和时间可分别省略；时间按北京时间解析，回复显示最终具体时间。 |
| 队列状态 | `/bd status` 读取当前账户的发布队列汇总。 |
| 任务详情（A2） | `/bd queue` 列最近任务，`/bd queue <任务ID>` 显示正文摘要、时间、失败原因及详情链接。 |
| B站账号状态（A5） | `/bd blogin` 显示最近一次登录检查、续期状态，不执行扫码或更改凭据。 |
| 使用帮助 | `/bd` 或 `/bd help`。 |
| 使用权限 | 可配置用户、群聊白名单；白名单为空时仅允许 AstrBot 管理员使用。群内使用还必须将该群加入白名单。 |

## 安装

1. 先更新并重启配套的 380nm 后端。此版本为 X 解析结果补充了原文；旧后端只返回截断标题和作者信息，插件会提示原文缺失。
2. **先停用原有 380nm AstrBot 插件**，避免一条消息被两个插件同时处理。
3. 通过 AstrBot 插件管理导入交付的 `dist/astrbot_plugin_380nm.zip`；也可将本目录放入 AstrBot 的 `data/plugins/astrbot_plugin_380nm/`，安装 `requirements.txt` 里的依赖后重启 AstrBot。
4. 在插件配置页填写下表中的连接和权限设置，保存并按 AstrBot 提示重载插件。

ZIP 交付包只包含插件。若 380nm 仍运行旧代码，仅安装 ZIP 不能补齐后端缺失的推文原文。

## 配置

建议在 380nm「用户管理」里创建一个专门供机器人使用的**普通用户**，再将这个用户的账号密码填入插件。创建普通用户需由 380nm 管理员操作。插件生成的模板、图片和草稿，以及它查询的发布队列，都属于这个 380nm 用户。

| 配置项 | 填写方式 |
| --- | --- |
| `base_url` | 380nm 服务根地址，例如 `http://192.168.1.20:8787`。不要填网页路径 `/drafts`；末尾有 `/api` 时会自动去掉。 |
| `username` | 上述 380nm 普通用户的用户名。 |
| `password` | 上述用户的登录密码；这是 380nm 密码，不是 AstrBot 或 X 的密码。 |
| `allowed_users` | 允许使用插件的机器人平台用户 ID 列表。未配置时，仅 AstrBot 管理员可用；配置后按名单授权。填写平台实际 ID，不要填昵称。 |
| `allowed_groups` | 允许使用的群 ID 列表。为空时不在群内处理；群已获授权时，发消息的用户也必须通过用户授权。私聊不需要群白名单。 |
| `request_timeout` | HTTP 请求超时，默认 `300` 秒，可设 `30`–`900` 秒；服务器抓取较慢时可调高。 |

插件通过 380nm 登录接口取得会话 Cookie，沿用后端的用户隔离。不要把账户密码或会话 Cookie 发到聊天消息中。

**Docker 地址提示：** AstrBot 容器内的 `127.0.0.1` / `localhost` 指向 AstrBot 容器自身。380nm 在另一个容器时，使用同一 Docker 网络中的服务名，例如 `http://380nm:8787`；在宿主机运行时，使用容器能访问的宿主机地址。先确保 AstrBot 所在环境能访问所填地址。

X 访问凭据 `auth_token` / `ct0` 和下载代理仍在 380nm「全站设置」配置。插件不需要再保存一份 X 凭据。

## 使用示例

向机器人发送，参数之间用空格分隔：

```text
/bd https://x.com/example/status/1234567890123456789
/bd https://x.com/example/status/1234567890123456789 作品标题
/bd https://x.com/example/status/1234567890123456789 明天晚上8点
/bd https://x.com/example/status/1234567890123456789 作品标题 明天20点
/bd https://x.com/example/status/1234567890123456789 "带 空格 的标题" 2026-12-25 20:30
/bd https://x.com/example/status/1234567890123456789 作品标题 12月25日
```

成功后回复的地址为 `服务地址/release?draft=草稿ID`，登录对应 380nm 用户即可直接打开这条草稿。正文包含原文、作者及来源；同一条推文的图片保存在同一条草稿中。草稿尚未发布，因此不会产生 B 站动态地址。

标题省略时使用作品标题摘要；自定义标题最多 20 个字（emoji 通常占 2 个字），超长会提示修改。标题中含空格或日期、时间词时使用英文或中文引号，例如 `"明天的约定"`。

时间统一为北京时间（UTC+8）：支持 `明天晚上8点`、`明天20点`、`后天晚上八点半`、`2026-12-25 20:30`、`12月25日` 等。只给日期默认当天 **20:00**，会明确提示；只给时钟取下一次对应时刻；省略时间则不设排期。无效日期、已过去的明确时间和无法识别的时间表达会要求重写。机器人回复会列出具体年月日和时分，便于核对。已有草稿重新发送时，仅更新本次明确提供的标题、时间，不清空省略的字段。

需要发布时，在网页上检查内容和时间，再执行入队操作。

查询状态或帮助：

```text
/bd status
/bd queue
/bd queue job_具体任务ID
/bd blogin
/bd help
```

`status` 显示发布队列五种状态数量、最多 5 条近期任务和 3 条最近失败任务，另显示正在抓取、等待抓取的数量；`queue` 查询具体任务、失败原因摘要与发布后的 B 站链接。`blogin` 显示后台最近一次检查的状态和时间，不代表即时验证。刚导入的内容在「草稿」中，尚未进入发布队列。

## 现有限制

- 本版只接入 X 图片推文；不提供视频下载或纯文字推文导入。视频封面图片也不代表视频文件已抓取。
- 受限推文是否能抓取，取决于 380nm 服务器的网络、X 凭据及该账户的可见范围。已删除或不可见的内容无法恢复。
- 使用旧后端时会收到原文缺失提示。已有草稿会被去重跳过，需在网页补填原文，或删除该草稿、更新后端后重新发送链接；不会将截断标题冒充完整原文。
- 重复检查针对当前账户现有草稿；手工删除草稿、发布后草稿被移除，或历史草稿没有 `variables.sourceUrl`，都可能再次导入。
- 一套插件配置连接一个 380nm 账户。被授权的聊天用户共用这套草稿和队列；群内的查询结果对群成员可见。若在多个平台使用，用户和群白名单按平台返回的原始 ID 匹配。
- 草稿类型沿用当前发布页、批量页使用的默认类型（后端名称为“原创”），正文明确保留 X 原作者和来源；不会自动创建 B 站账号库成员。旧“转载”类型要求额外绑定账号库原作者，与本次链接署名流程不同。
- 同一实例串行抓取，最多接受 10 个等待中的抓取请求；处理中重启插件会中断未完成的请求，检查网页后可重新发送。去重不能保证多个 AstrBot 实例同时导入同一作品时不重复。
- 插件不包含发布、取消、删除、账号凭据管理等额外命令。下表中已接入的功能会明确标注，其余仍为候选。

## 可选功能清单：由你决定是否增加

成本是基于当前项目接口的相对开发量，不是工时承诺。可直接回复编号，例如“加 A1、A3、B2”。

### A. 小改动：已有接口可以直接复用

| 编号 | 候选功能 | 可以做到什么 / 现有依据 |
| --- | --- | --- |
| A1 | 草稿清单与数量 | 查最近草稿、缺少哪些字段，复用 `GET /api/drafts`。 |
| A2 | 任务详情与失败原因 | **已实现：`/bd queue [任务ID]`。** |
| A3 | 只看失败 / 今日待发布 | 为队列命令增加状态、日期筛选，无须改变发布逻辑。 |
| A4 | 抓取时指定图库文件夹 | 从已有文件夹选择，抓取接口已接收 `folderId`。 |
| A5 | B 站账号状态查询 | **已实现：`/bd blogin`。** |
| A6 | 最近运行日志 | 从 `GET /api/logs` 展示当前用户最近操作或失败信息。 |

### B. 中等改动：需要增加机器人交互或状态管理

| 编号 | 候选功能 | 可以做到什么 / 额外工作 |
| --- | --- | --- |
| B1 | Pixiv 链接存草稿 | 后端 `parse-work` 已能抓取 Pixiv 原图及作者；插件需增加识别和署名格式。若要求作品完整说明，也要扩展后端元数据。 |
| B2 | 抓取或发布结果主动通知 | 插件轮询草稿/任务状态并记录消息会话，仅在状态变化时通知；需要持久化通知记录。 |
| B3 | 聊天中编辑草稿、设置发布时间 | **标题和时间已实现**：再次 `/bd <同一X链接> [标题] [时间]` 更新已有草稿。正文编辑、按草稿ID选择仍为候选。 |
| B4 | 草稿入队、取消、重试、立即发布 | 后端已有对应接口；机器人需增加明确的操作命令及防误操作确认。现有草稿入队使用该用户首个 B 站账号。 |
| B5 | 给机器人发图片保存为草稿 | 复用上传接口，但需适配聊天平台附件下载。现有 `/api/drafts/upload` 每张图生成一条草稿；多图合并需另行编排。 |
| B6 | 更多链接的批量导入与进度 | 加入独立抓取任务队列、限速、进度和失败重试，避免一条消息等待太久。 |
| B7 | 草稿图片预览 | 使用有鉴权的原图/缩略图接口，由机器人获取后作为图片发送；不能直接向聊天用户暴露会话 Cookie。 |

### C. 需补充后端能力或新增服务

| 编号 | 候选功能 | 当前缺口 |
| --- | --- | --- |
| C1 | 纯文字 X 推文导入 | 当前作品抓取流程要求存在图片，需要将取元数据与下载图片拆开。 |
| C2 | X 视频下载并发布 | 需要视频解析、下载、存储，以及与 B 站发布方式配套的处理；现有流程是图文动态。 |
| C3 | 跨草稿和历史发布的永久去重 | 当前无可靠的来源索引；需要持久化来源 ID，并定义删除、重新抓取的行为。 |
| C4 | 草稿入队时任选 B 站账号 | 现有草稿入队接口固定使用首个账号，需要增加并校验目标账号参数。 |
| C5 | 自动翻译作者原文 | 需要选定翻译服务或模型、配置调用方式，并确定保留原文还是双语展示。 |
| C6 | 为每个聊天用户绑定独立 380nm 账户 | 需要账户绑定、凭据保存、权限校验和解除绑定流程。 |
| C7 | 后端推送发布完成或失败事件 | 当前没有面向插件的事件订阅/Webhook；可先采用 B2 的轮询方式。 |

## 验证

在项目根目录执行本地检查：

```powershell
python -m pip install -r plugins/astrbot_plugin_380nm/requirements.txt
python -m unittest discover -s plugins/astrbot_plugin_380nm/tests
npm run check
npm test
python scripts/package-astrbot.py
```

自动化检查不能代替真实 AstrBot、X 和部署环境的联调。首次启用后，用 `/bd <自己能访问的图片推文>` 验证草稿原文、作者信息及直达地址，再测试自定义标题和时间、重复作品更新、`status` / `queue` / `blogin` 是否读取正确账户。实际线上联调结果以部署后的验证为准。

开发接口参考：[AstrBot 消息事件](https://docs.astrbot.app/dev/star/guides/listen-message-event.html)、[插件配置](https://docs.astrbot.app/dev/star/guides/plugin-config.html)。
